Development Operations · agentic AI skill prototype

Protocol Eligibility Copilot

Eligibility criteria decide how fast a trial can enrol, how many patients fail screening, and how many protocol amendments follow. This prototype turns the criteria of a real protocol into structured, reviewable data: each criterion is categorised, its thresholds and washout windows are pulled out, and anything a feasibility reviewer should question is flagged. It then benchmarks the protocol against completed trials in the same indication and phase.

The point of the exercise is the method as much as the tool. I picked one Development Operations workflow, set a baseline, built the skill with frontier agentic tools, measured it against that baseline on quality, cost, latency and consistency, and wrote down what it would take to use it in a GxP setting.

2 · Evaluation vs baseline

Does the skill beat the baseline, and at what cost?

Reference set: 70 criteria from 5 GSK/ViiV Phase 3 protocols across respiratory, oncology, HIV, vaccines and immunology, each given a reference category. Where a compound criterion fits two categories, both are accepted (lenient); strict accuracy counts only the primary label. The baseline is a keyword classifier written before any model ran and not tuned afterwards. Each model was run twice per protocol, at low reasoning effort, through headless Claude Code with tools disabled.

3 · Agentic design

Design choices, mapped to how agentic systems fail

I built this as a constrained workflow rather than a free-roaming agent. Orchestration is deterministic and the model is called at one step, with a fixed contract. That makes it cheaper to validate and easier to explain to Quality, and it leaves room to add autonomy where it pays.

ContextEach call gets one protocol: the study metadata, the deterministically split criteria with stable IDs, and the taxonomy definitions. No retrieval guesswork and no patient data. The prompt is generated from the same taxonomy object the baseline and the scorer use.
MemoryStateless by design: nothing carries between protocols, so results are reproducible. The only durable state is the reviewer audit trail, plus the frozen CT.gov snapshot used for evaluation. Cross-study memory, such as a library of past amendments, is a next step with its own governance.
Tool useTwo tools: get_study and find_comparators, both against the public ClinicalTrials.gov API v2. Tools are deterministic, so their outputs can be tested like ordinary code.
OrchestrationFetch → split → classify → benchmark → human review. Fixed order, with fallbacks at each step: the rule baseline if no model is available, and the frozen snapshot if the registry is unreachable.
EvaluationA reference set, a pre-registered baseline, and four metrics: accuracy, cost, latency and run-to-run agreement. The harness (eval/run_eval.mjs) reruns end to end with one command, so a model or prompt change gets re-scored before it ships.
ReliabilityOutputs are schema-checked and fail closed: a missing or malformed answer becomes NEEDS_REVIEW and is never silently defaulted. Two runs per protocol measure consistency. A named human signs off every output.
4 · Clinical context

Where this sits in clinical development

Eligibility criteria are written at protocol design but their cost lands later, in feasibility, screen failure, recruitment timelines and amendments. ICH E8(R1) asks sponsors to design quality in by focusing on factors critical to quality. FDA's 2020 guidance on eligibility criteria and the ASCO–Friends of Cancer Research recommendations push back on exclusions that are not scientifically necessary. This skill gives study teams that challenge at design time, before sites see the protocol.

5 · How it was built

Built in a day, with the evidence attached

Built in one day with Claude Code as the agentic development environment. The pieces: lib.js holds the splitter, baseline, taxonomy, prompt and scorer, shared by this page and the evaluation harness so the two cannot drift apart. skills/eligibility-criteria-structurer/SKILL.md packages the step as a reusable agent skill, with its standards. eval/ holds the frozen protocols, reference labels, raw model runs and the harness.

Limitations. The reference set is small (70 criteria), and the labels were drafted with AI assistance before human review, which can favour model-style labelling. The categories are deliberately coarse, so the task saturates. The feasibility flags and thresholds are shown but not yet scored. Costs come from Claude Code's harness at list price, so they are an upper bound on a direct API call. Manual review time has not been measured yet; a time-and-motion baseline with study teams is the next step before any value claim on cycle time.

Prototype for discussion. Uses only public registry data from ClinicalTrials.gov and makes no eligibility decision about any patient. Not affiliated with or endorsed by GSK.
